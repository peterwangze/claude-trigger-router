## 二、当前偏离性质判断

当前存在偏离，但主要不是方向性偏离，而是管理视图偏离：

### 1. 跟踪文档状态落后

`docs/superpowers/plans/2026-04-04-router-evolution-tracker.md` 中：

这说明文档视图未及时同步到真实实现进度。

### 2. setup 文档仍停留在执行前态

`docs/superpowers/plans/2026-04-02-ctr-setup.md` 仍保留初始 checklist 形态，但 `src/setup/` 代码和测试已经完成首轮落地，文档未反映这一点。

### 3. 配置易用性工作未被正式纳入路线图

实际上，项目已经新增并持续强化以下能力：

- `Models` 抽象
- setup 生成 models 配置
- provider template
- `/ui` 配置草稿编辑
- 编译结果预览与 diff
- 引用影响分析、修复建议、自动修复
- preset merge / dry-run / impact summary

这些能力已经构成独立主线，但此前并未在正式路线图中得到明确位置。

## 三、当前真实阶段定义

截至 2026-04-06，建议把当前项目阶段定义为：

### 主线一：治理与观测运营

目标：

- 继续增强 metrics、导出、归档、异常检测、时间窗趋势
- 把治理链路从“可调试”推进到“可运营”

### 主线二：配置产品化

目标：

- 统一模型抽象
- 降低 provider 差异暴露
- 让 setup、配置文件、`/ui` 使用同一套编译和校验逻辑
- 持续收敛首次使用和配置修改的复杂度

## 四、下一阶段建议

接下来建议正式把以下问题列为下一阶段目标：

1. 单模型配置是否可进一步收敛为 `api` / `key` / `接口类型` / `思考类型（可选）`
2. OpenAI / Anthropic 及其他兼容服务是否能统一进入一套模型抽象
3. 是否由路由层统一完成消息格式转换，而不是要求各入口理解 provider 差异
4. setup、配置文件和 `/ui` 是否能完全共享同一份模型 schema、编译器和校验器

## 五、建议动作

建议后续按如下顺序推进：

1. 先完成本轮文档校准，消除计划视图偏差
2. 为“配置产品化”补一份正式路线图或阶段计划
3. 再进入“最简模型配置参数 + 协议统一转换”第二阶段设计和实现
